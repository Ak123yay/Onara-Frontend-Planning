STEP 1

Account Setup &amp; Prerequisites

Creating every service account, installing tools, and generating all API keys before writing a single line of code.

Why This Step Comes First

Every Onara service — Supabase, Vercel, Cloudflare, Stripe, GitHub, Google Cloud, Resend — requires an account, and many require cross-referencing credentials between services. Setting everything up at once means you have a master list of keys before writing code, so you never get blocked mid-development waiting for an approval email or a key to propagate. It also lets you identify any service limitations (e.g., GitHub Education verification takes 24-72 hours) before they become critical-path blockers.

1.1  GitHub Accounts

Onara uses a single GitHub account for everything. The GitHub App (Onara Deployer) handles the security isolation that previously required a personal account, by scoping access to onara-sites only.

Personal Development Account

Go to github.com and create or confirm your personal account.

Navigate to github.com/education and click &quot;Get benefits for students.&quot;

Submit verification with your student email address. Approval takes 24-72 hours.

Once approved, confirm GitHub Copilot is enabled: Settings &gt; Copilot &gt; Enable for your account.

Generate a fine-grained Personal Access Token for Copilot SDK auth: Settings &gt; Developer Settings &gt; Personal access tokens &gt; Fine-grained tokens &gt; Generate new token.

Token name: Onara. Expiration: 90 days.

Repository access: None. Permissions: Copilot Requests → Read only. No other permissions needed.

Copy and save as COPILOT_GITHUB_TOKEN.

Deployments — GitHub App

Onara pushes generated site code to GitHub automatically via a GitHub App. This gives the agents write access to the onara-sites repo only — nothing else on your account. Token rotation is automatic (tokens expire hourly and regenerated on demand). This is the only approach used — no PAT.

GitHub App Setup

Go to your GitHub account: Settings &gt; Developer Settings &gt; GitHub Apps &gt; New GitHub App.

Name it &quot;Onara Deployer&quot;. Set Homepage URL to your domain or a placeholder.

Under Permissions, set: Repository permissions &gt; Contents: Read &amp; Write. Repository permissions &gt; Metadata: Read only. Leave everything else as No access.

Under &quot;Where can this GitHub App be installed?&quot; select &quot;Only on this account.&quot;

Click Create GitHub App. Note the App ID shown at the top of the next screen.

Scroll down to Private keys &gt; Generate a private key. A .pem file downloads automatically. Store it securely — treat it like a password.

Click Install App in the sidebar. Install on your account and when prompted select &quot;Only select repositories&quot; and choose onara-sites only.

After installation, note the Installation ID from the URL bar: /settings/installations/{installation_id}.

Save App ID as GITHUB_APP_ID, Installation ID as GITHUB_APP_INSTALLATION_ID, and the contents of the .pem file as GITHUB_APP_PRIVATE_KEY in your credentials file.

GitHub App Token Generation in FastAPI

GitHub App installation tokens expire after 1 hour. Generate them on demand rather than storing them. Add this utility to lib/github_auth.py:

# lib/github_auth.py

import jwt, time, httpx, os

APP_ID = os.getenv(&quot;GITHUB_APP_ID&quot;)

INSTALLATION_ID = os.getenv(&quot;GITHUB_APP_INSTALLATION_ID&quot;)

PRIVATE_KEY = os.getenv(&quot;GITHUB_APP_PRIVATE_KEY&quot;).replace(&quot;\\n&quot;, &quot;\n&quot;)

def generate_installation_token() -&gt; str:

    &quot;&quot;&quot;Generate a fresh GitHub App installation token (valid 1 hour).&quot;&quot;&quot;

    payload = {

        &quot;iat&quot;: int(time.time()) - 60,  # issued 60s ago to account for clock drift

        &quot;exp&quot;: int(time.time()) + 540,  # expires in 9 minutes

        &quot;iss&quot;: APP_ID,

    }

    jwt_token = jwt.encode(payload, PRIVATE_KEY, algorithm=&quot;RS256&quot;)

    r = httpx.post(

        f&quot;https://api.github.com/app/installations/{INSTALLATION_ID}/access_tokens&quot;,

        headers={

            &quot;Authorization&quot;: f&quot;Bearer {jwt_token}&quot;,

            &quot;Accept&quot;: &quot;application/vnd.github+json&quot;,

        }

    )

    r.raise_for_status()

    return r.json()[&quot;token&quot;]  # use this exactly like a PAT

In lib/githubBackup.js (Next.js), call the FastAPI /github/token endpoint to get a fresh installation token, then use it exactly like a PAT in the Authorization header. The REST API calls are identical.

Why a Monorepo for Sites?

Creating a new GitHub repo per site would exhaust the API rate limit very quickly. One monorepo with folders per site is dramatically more efficient and keeps all code in one place for backup and auditing.

1.5  Cloudflare

onara.tech vs Cloudflare Pages URLs — Important Distinction

These are two completely separate things:

onara.tech — YOUR domain, which you bought. Your Next.js app lives here. You point this at Vercel (not Cloudflare).

{projectId}.pages.dev — Cloudflare gives this FREE subdomain to every site your users generate. Your users&apos; generated sites live here.

So: onara.tech is your app. onara-site-abc123.pages.dev is a user&apos;s generated site. Cloudflare does not give you onara.tech — you already own that and point it at Vercel.

1.9  Development Environment Setup

Onara runs across two machines during development. Your main PC handles all local Ollama AI model inference — the compute-heavy job that benefits from dedicated RAM. Your mini PC runs everything else: Next.js, FastAPI pipeline server, Cloudflare tunnel, and Stripe CLI. This split keeps the AI models from competing with server processes for memory.

Two-Machine Dev Split

PC: Ollama only. Runs qwen3:8b and llama3.3:8b. FastAPI calls it over your local network via http://PC_LOCAL_IP:11434

Mini PC: Everything else. Next.js (port 3000), FastAPI pipeline server (port 8000), Stripe CLI, Cloudflare tunnel. This is where you write code and run servers.

2.5  Create a Working main.py (FastAPI Skeleton)

Write the minimal FastAPI entry point now. You will expand each route in Step 5 and Step 6. This skeleton proves the server starts and exposes the /health endpoint that UptimeRobot will later monitor.

# onara-pipeline/main.py

from fastapi import FastAPI, Depends, HTTPException, Header

from fastapi.middleware.cors import CORSMiddleware

import os, json

from dotenv import load_dotenv

load_dotenv()

PIPELINE_SECRET = os.getenv(&quot;PIPELINE_SECRET&quot;)

app = FastAPI(title=&quot;Onara Pipeline&quot;)

app.add_middleware(

    CORSMiddleware,

    allow_origins=[&quot;https://onara-app.vercel.app&quot;, &quot;http://localhost:3000&quot;],

    allow_methods=[&quot;*&quot;],

    allow_headers=[&quot;*&quot;],

)

def verify_secret(x_pipeline_secret: str = Header(None)):

    if x_pipeline_secret != PIPELINE_SECRET:

        raise HTTPException(status_code=401, detail=&quot;Unauthorized&quot;)

@app.get(&quot;/health&quot;)

async def health():

    return {&quot;status&quot;: &quot;ok&quot;, &quot;queue_length&quot;: 0}

@app.post(&quot;/pipeline/start&quot;)

async def start_pipeline(body: dict, _=Depends(verify_secret)):

    return {&quot;jobId&quot;: body.get(&quot;jobId&quot;), &quot;status&quot;: &quot;queued&quot;}

@app.get(&quot;/pipeline/status/{job_id}&quot;)

async def pipeline_status(job_id: str, _=Depends(verify_secret)):

    return {&quot;jobId&quot;: job_id, &quot;phase&quot;: &quot;pending&quot;}

STEP 3

Supabase: Database, Auth &amp; Storage

Creating the full database schema, enabling Row Level Security, configuring Google OAuth, and setting up the storage bucket.

Why Database-First Development Works

Building your data layer before your UI prevents the most expensive architectural mistake in web development: designing your UI and then discovering your schema cannot support it. Every feature in Onara — billing, revisions, site management, trial expiry — is driven by database state. Getting the schema right now means all subsequent steps build on a solid foundation.

3.1  Create the Database Schema

In the Supabase dashboard, go to the SQL Editor and run the following complete schema. Run it as a single script.

-- ============================================================

-- Onara Database Schema v1

-- Run in Supabase SQL Editor

-- ============================================================

CREATE TABLE users (

  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  email                 VARCHAR(255) UNIQUE NOT NULL,

  password_hash         VARCHAR(255),          -- NULL for OAuth users

  plan                  TEXT DEFAULT &apos;free&apos;,

  sub_status            TEXT DEFAULT &apos;inactive&apos;,

  stripe_customer_id    VARCHAR(255),

  stripe_subscription_id VARCHAR(255),

  referral_code         VARCHAR(32) UNIQUE DEFAULT

                        substring(md5(random()::text), 1, 8),

  trial_ends_at         TIMESTAMPTZ,

  is_trial              BOOLEAN DEFAULT FALSE,

  referred_by           UUID REFERENCES users(id),

  created_at            TIMESTAMPTZ DEFAULT NOW()

);

CREATE TABLE projects (

  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  user_id               UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

3.4  Create the Supabase Auth Trigger

When a user signs up via Google OAuth, Supabase creates a record in auth.users but not in your public users table. This trigger automatically creates the corresponding public users record, sets the reverse trial, and generates a referral code.

CREATE OR REPLACE FUNCTION handle_new_user()

RETURNS TRIGGER AS $$

BEGIN

  INSERT INTO public.users (id, email, is_trial, plan, trial_ends_at)

  VALUES (

    NEW.id,

    NEW.email,

    TRUE,

    &apos;pro&apos;,

    NOW() + INTERVAL &apos;14 days&apos;

  );

  RETURN NEW;

END;

$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created

  AFTER INSERT ON auth.users

  FOR EACH ROW EXECUTE FUNCTION handle_new_user();

4.3  Route Protection Middleware

Create middleware.js at the root of the Next.js app. This runs before every request and redirects unauthenticated users away from protected routes.

// middleware.js (root of onara-app/)

import { createMiddlewareClient } from &apos;@supabase/auth-helpers-nextjs&apos;

import { NextResponse } from &apos;next/server&apos;

export async function middleware(req) {

  const res = NextResponse.next()

  const supabase = createMiddlewareClient({ req, res })

  const { data: { session } } = await supabase.auth.getSession()

  const { pathname } = req.nextUrl

  const isProtected = pathname.startsWith(&apos;/dashboard&apos;)

  const isAuth = pathname.startsWith(&apos;/login&apos;) || pathname.startsWith(&apos;/signup&apos;)

  if (isProtected &amp;&amp; !session) {

    return NextResponse.redirect(new URL(&apos;/login&apos;, req.url))

  }

  if (isAuth &amp;&amp; session) {

    return NextResponse.redirect(new URL(&apos;/dashboard&apos;, req.url))

  }

  return res

}

FastAPI Pipeline Server: Skeleton &amp; Queue

Architecture of the Pipeline Server

The FastAPI pipeline server is the brain of Onara. It receives generation requests from Next.js, manages a job queue so multiple users are handled safely, runs all ten agents sequentially, and returns validated code to the Next.js backend for deployment. Before implementing any agent logic, you need the infrastructure — the queue, the blackboard, the supervisor, and the job state management — to be solid.

5.2  The In-Memory Job Queue

The queue is built on Python asyncio. It processes one job at a time and stores job states in a dictionary for status polling. A SQLite log provides recovery on crash.

# main.py — complete queue implementation

from fastapi import FastAPI, HTTPException, Header

from fastapi.responses import StreamingResponse

import asyncio, os, json, time, sqlite3

from dotenv import load_dotenv

from lib.blackboard import create_blackboard

load_dotenv()

app = FastAPI()

# In-memory stores

job_store: dict = {}          # job_id -&gt; blackboard

pipeline_queue = asyncio.Queue()

is_processing = False

# SQLite for crash recovery

conn = sqlite3.connect(&apos;jobs.db&apos;)

conn.execute(&apos;&apos;&apos;CREATE TABLE IF NOT EXISTS jobs

  (id TEXT PRIMARY KEY, status TEXT, created_at REAL)&apos;&apos;&apos;)

def verify_secret(x_pipeline_secret: str = Header(None)):

    if x_pipeline_secret != os.getenv(&quot;PIPELINE_SECRET&quot;):

        raise HTTPException(status_code=401)

async def process_next():

    global is_processing

    is_processing = True

    while not pipeline_queue.empty():

        job_id = await pipeline_queue.get()

        bb = job_store[job_id]

        bb[&apos;phase&apos;] = &apos;running&apos;

        try:

            from agents.pipeline import run_pipeline

            await run_pipeline(bb)

        except Exception as e:

            bb[&apos;phase&apos;] = &apos;error&apos;

            bb[&apos;errors&apos;].append(str(e))

        conn.execute(&apos;UPDATE jobs SET status=? WHERE id=?&apos;, (bb[&apos;phase&apos;], job_id))

        conn.commit()

    is_processing = False

@app.post(&quot;/pipeline/start&quot;)

async def start_pipeline(body: dict, _=Depends(verify_secret)):

    job_id = body[&quot;jobId&quot;]

    bb = create_blackboard(job_id, body[&quot;businessData&quot;], body.get(&quot;stylePrefs&quot;, {}))

    job_store[job_id] = bb

    conn.execute(&apos;INSERT OR IGNORE INTO jobs VALUES (?,?,?)&apos;,

                 (job_id, &apos;queued&apos;, time.time()))

    conn.commit()

    await pipeline_queue.put(job_id)

    queue_size = pipeline_queue.qsize()

    if not is_processing:

        asyncio.create_task(process_next())

    return {&quot;jobId&quot;: job_id, &quot;queuePosition&quot;: queue_size}

5.3  The Supervisor Agent

The Supervisor runs after every agent completes and checks the latest output against the overall project goals. It catches errors before they propagate downstream, saving token usage and improving output quality. It uses the fast local llama3.3:8b model — free and adds minimal latency.

async def supervise(agent_name: str, output: dict, blackboard: dict) -&gt; dict:

    prompt = SUPERVISOR_PROMPT.format(

        business_type=blackboard[&apos;business_data&apos;].get(&apos;type&apos;, &apos;small business&apos;),

        agent_name=agent_name,

            [&apos;analyst_output&apos;, &apos;content_output&apos;, &apos;style_output&apos;] if blackboard[k]}, indent=2)[:500]

5.4  The Ollama Client Wrapper

All AI calls go through ollama_client.py. Local models run on your PC. Cloud models use Ollama cloud free tier. Every cloud call auto-falls back to llama3.3:8b locally on rate limit or error.

# lib/ollama_client.py

import os

from ollama import Client

from dotenv import load_dotenv

load_dotenv()

OLLAMA_API_KEY   = os.getenv(&quot;OLLAMA_API_KEY&quot;)

OLLAMA_LOCAL_URL = os.getenv(&quot;OLLAMA_LOCAL_URL&quot;, &quot;http://localhost:11434&quot;)

# Local client — your PC on the network

local_client = Client(host=OLLAMA_LOCAL_URL)

# Cloud client — Ollama cloud free tier

cloud_client = Client(

    host=&quot;https://ollama.com&quot;,

    headers={&quot;Authorization&quot;: f&quot;Bearer {OLLAMA_API_KEY}&quot;}

)

async def ollama_local(model: str, prompt: str) -&gt; str:

    import asyncio

    loop = asyncio.get_event_loop()

    r = await loop.run_in_executor(None, lambda: local_client.chat(

        model=model, messages=[{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: prompt}]))

    return r.message.content

async def ollama_cloud(model: str, prompt: str,

                       fallback: str = &quot;llama3.3:8b&quot;) -&gt; str:

    # Auto-falls back to local on rate limit or error

    import asyncio

    loop = asyncio.get_event_loop()

    try:

        r = await loop.run_in_executor(None, lambda: cloud_client.chat(

            model=model, messages=[{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: prompt}]))

        return r.message.content

    except Exception as e:

        print(f&quot;Cloud fallback to {fallback}: {e}&quot;)

        return await ollama_local(fallback, prompt)

5.5  Pipeline Orchestrator

Create the main pipeline runner that calls all ten agents in sequence, runs the supervisor between each, handles parallelism for agents 2 and 3, and manages preloading.

# agents/pipeline.py

import asyncio

from agents.supervisor import supervise

from agents import analyst, content_writer, style_agent, planner

from agents import prompt_engineer, code_generator, debugger, seo_agent, qa_agent, mobile_optimizer

async def run_pipeline(blackboard: dict):

    &quot;&quot;&quot;Run the full 10-agent pipeline with supervisor checks.&quot;&quot;&quot;

    async def run_with_supervision(agent_fn, agent_name, *args, key=None):

        for attempt in range(3):

            blackboard[&quot;active_agent&quot;] = agent_name

            result = await agent_fn(blackboard)

            review = await supervise(agent_name, result, blackboard)

            if review[&quot;approved&quot;]:

                if key: blackboard[key] = result

                return result

            # Re-run with correction injected into blackboard

            blackboard[&quot;supervisor_correction&quot;] = review[&quot;correction&quot;]

        raise RuntimeError(f&quot;{agent_name} failed supervisor after 3 attempts&quot;)

    # Agent 1: Business Analyst

    await run_with_supervision(analyst.run, &quot;Business Analyst&quot;, key=&quot;analyst_output&quot;)

    # Agents 2 + 3: Run in parallel

    content, style = await asyncio.gather(

        content_writer.run(blackboard),

        style_agent.run(blackboard)

    )

    blackboard[&quot;content_output&quot;] = content

    blackboard[&quot;style_output&quot;] = style

    # Agents 4-9: Sequential

    await run_with_supervision(planner.run, &quot;Planner&quot;, key=&quot;blueprint&quot;)

    await run_with_supervision(prompt_engineer.run, &quot;Prompt Engineer&quot;, key=&quot;prompt&quot;)

    await run_with_supervision(code_generator.run, &quot;Code Generator&quot;, key=&quot;raw_code&quot;)

    await run_with_supervision(debugger.run, &quot;Debugger&quot;, key=&quot;debugged_code&quot;)

    await run_with_supervision(seo_agent.run, &quot;SEO Agent&quot;, key=&quot;seo_code&quot;)

    result = await qa_agent.run(blackboard)

    blackboard[&quot;qa_result&quot;] = result

    blackboard[&quot;qa_approved_code&quot;] = blackboard[&quot;seo_code&quot;]

    if not result.get(&quot;approved&quot;):

        raise RuntimeError(f&quot;QA failed: {result.get(&apos;issues&apos;, [])}&quot;)

    # Agent 10: Mobile Optimization (final pass)

    blackboard[&quot;active_agent&quot;] = &quot;Mobile Optimizer&quot;

    await mobile_optimizer.run(blackboard)

    blackboard[&quot;phase&quot;] = &quot;done&quot;

Onara uses 10 agents in sequence — each with one specific job. Set up the ChromaDB vector database and populate it with HTML/CSS/JS patterns before implementing the Debugger and QA agents. This is a one-time setup that runs when the server starts.

# rag/vector_store.py

import chromadb

from sentence_transformers import SentenceTransformer

from rank_bm25 import BM25Okapi

model = SentenceTransformer(&quot;all-MiniLM-L6-v2&quot;)

client = chromadb.PersistentClient(path=os.getenv(&quot;CHROMA_PATH&quot;, &quot;./chroma_db&quot;))  # persistent, not in-memory

def get_collection():

    return client.get_or_create_collection(&quot;onara-patterns&quot;)

def embed_documents(docs: list[dict]):

    &quot;&quot;&quot;docs is list of {id, content, metadata}&quot;&quot;&quot;

    collection = get_collection()

    embeddings = model.encode([d[&quot;content&quot;] for d in docs]).tolist()

    collection.add(

        ids=[d[&quot;id&quot;] for d in docs],

        documents=[d[&quot;content&quot;] for d in docs],

        embeddings=embeddings,

        metadatas=[d.get(&quot;metadata&quot;, {}) for d in docs],

    )

def hybrid_search(query: str, n_results: int = 3) -&gt; list[str]:

    collection = get_collection()

    embedding = model.encode(query).tolist()

    vector_results = collection.query(

        query_embeddings=[embedding], n_results=n_results * 2

    )

    docs = vector_results[&quot;documents&quot;][0]

    if not docs: return []

    # BM25 reranking

    tokenized = [d.split() for d in docs]

    bm25 = BM25Okapi(tokenized)

    scores = bm25.get_scores(query.split())

    ranked = sorted(zip(docs, scores), key=lambda x: x[1], reverse=True)

    return [d for d, _ in ranked[:n_results]]

7.1  How the Business Search Works — Google Places API

The user types their business name into Step 1 of the build flow. That string is sent to /api/places which calls the Google Places Text Search API. The API returns the best matching business with its full profile — name, address, phone, hours, photos, and type. If any fields are missing (e.g. no phone number on file), Onara highlights them in amber and lets the user fill them in manually before continuing. This is the only required user input before generation.

What the user actually does

User types: &quot;Mikes Pizza Austin TX&quot; (or just &quot;Mikes Pizza&quot; — the API handles partial names)

Onara calls Places API → returns the matching Google Business listing

User sees a confirmation card with their real name, address, phone, hours, and photo

Missing fields show an amber badge and an editable input inline

User clicks Confirm and Continue → generation starts

7.2  The /api/places Route — Implementation

// app/api/places/route.js

import { NextResponse } from &apos;next/server&apos;

const PLACES_KEY = process.env.GOOGLE_PLACES_API_KEY

export async function GET(req) {

  const { searchParams } = new URL(req.url)

  const q = searchParams.get(&apos;q&apos;)

  if (!q) return NextResponse.json({ error: &apos;Missing query&apos; }, { status: 400 })

  const searchUrl = `https://maps.googleapis.com/maps/api/place/textsearch/json?query=${encodeURIComponent(q)}&amp;key=${PLACES_KEY}`

  const searchRes = await fetch(searchUrl)

  const searchData = await searchRes.json()

  if (!searchData.results?.length) {

    return NextResponse.json({ found: false })

  }

  const place = searchData.results[0]

  const detailUrl = `https://maps.googleapis.com/maps/api/place/details/json?place_id=${place.place_id}&amp;fields=name,formatted_address,formatted_phone_number,opening_hours,photos,website,types&amp;key=${PLACES_KEY}`

  const detailRes = await fetch(detailUrl)

  const detail = await detailRes.json()

  const p = detail.result

  // Identify missing fields

  const missing = []

  if (!p.formatted_phone_number) missing.push(&apos;phone&apos;)

  if (!p.opening_hours) missing.push(&apos;hours&apos;)

  return NextResponse.json({

    found: true,

    data: {

      name: p.name,

      address: p.formatted_address,

      phone: p.formatted_phone_number || null,

      hours: p.opening_hours?.weekday_text || null,

      photos: p.photos?.slice(0, 3).map(ph =&gt; `https://maps.googleapis.com/maps/api/place/photo?maxwidth=400&amp;photoreference=${ph.photo_reference}&amp;key=${PLACES_KEY}`) || [],

      types: p.types || [],

    },

    missing,

  })

}

// app/api/sites/route.js

import { NextResponse } from &apos;next/server&apos;

import { getServiceClient } from &apos;@/lib/supabase&apos;

import { createClient } from &apos;@supabase/supabase-js&apos;

import crypto from &apos;crypto&apos;

const PIPELINE_URL = process.env.PIPELINE_SERVER_URL

const PIPELINE_SECRET = process.env.PIPELINE_SECRET

export async function POST(req) {

  const supabase = getServiceClient()

  const { data: { user } } = await supabase.auth.getUser(

    req.headers.get(&apos;Authorization&apos;)?.replace(&apos;Bearer &apos;, &apos;&apos;)

  )

  if (!user) return NextResponse.json({ error: &apos;Unauthorized&apos; }, { status: 401 })

  const body = await req.json()

  const jobId = crypto.randomBytes(16).toString(&apos;hex&apos;)

  // Forward to FastAPI pipeline

  const pipelineRes = await fetch(`${PIPELINE_URL}/pipeline/start`, {

    method: &apos;POST&apos;,

    headers: { &apos;Content-Type&apos;: &apos;application/json&apos;, &apos;x-pipeline-secret&apos;: PIPELINE_SECRET },

    body: JSON.stringify({ jobId, businessData: body.businessData, extraContext: body.extraContext, stylePrefs: body.stylePrefs }),

  })

  if (!pipelineRes.ok) return NextResponse.json({ error: &apos;Pipeline error&apos; }, { status: 500 })

  const { queuePosition } = await pipelineRes.json()

  // Create project record in Supabase

  await supabase.from(&apos;projects&apos;).insert({

    user_id: user.id,

    project_id: jobId,

    business_name: body.businessData.name,

    status: &apos;generating&apos;,

  })

  return NextResponse.json({ jobId, queuePosition })

}

function statusIcon(agent, activeAgent, completedAgents, errorAgent) {

  if (errorAgent === agent) return { icon: &apos;✗&apos;, color: &apos;text-red-500&apos; }

  if (completedAgents.includes(agent)) return { icon: &apos;✓&apos;, color: &apos;text-green-500&apos; }

  if (activeAgent === agent) return { icon: &apos;⟳&apos;, color: &apos;text-gold animate-spin&apos; }

  return { icon: &apos;○&apos;, color: &apos;text-gray-300&apos; }

export default function AgentProgress({ jobId, onComplete }) {

      const res = await fetch(`/api/sites/${jobId}/status`)

      if (data.phase === &apos;done&apos;) { clearInterval(iv); onComplete(data) }

      // Track completed agents based on ordering

      const idx = AGENTS.findIndex(a =&gt; a === data.activeAgent)

    }, 3000)

    return () =&gt; clearInterval(iv)

    cancel_url: `${process.env.NEXT_PUBLIC_APP_URL}/dashboard`,

    customer_email: user.email,

    metadata: { userId: user.id, plan },

  })

  return NextResponse.json({ url: session.url })

}

8.2  Stripe Webhook Handler

// app/api/webhooks/stripe/route.js

import { NextResponse } from &apos;next/server&apos;

import Stripe from &apos;stripe&apos;

import { getServiceClient } from &apos;@/lib/supabase&apos;

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY)

export async function POST(req) {

  const body = await req.text()

  const sig = req.headers.get(&apos;stripe-signature&apos;)

  let event

  try {

    event = stripe.webhooks.constructEvent(body, sig, process.env.STRIPE_WEBHOOK_SECRET)

  } catch {

    return NextResponse.json({ error: &apos;Invalid signature&apos; }, { status: 400 })

  }

  const supabase = getServiceClient()

  if (event.type === &apos;checkout.session.completed&apos;) {

    const { userId, plan } = event.data.object.metadata

    const revisions = plan === &apos;pro&apos; ? 9999 : 10

    await supabase.from(&apos;users&apos;).update({

      plan, sub_status: &apos;active&apos;,

      stripe_customer_id: event.data.object.customer,

      stripe_subscription_id: event.data.object.subscription,

      is_trial: false,

    }).eq(&apos;id&apos;, userId)

    // Set show_url true for all user projects

    await supabase.from(&apos;projects&apos;).update({ show_url: true, revisions_allowed: revisions }).eq(&apos;user_id&apos;, userId)

  }

  if (event.type === &apos;customer.subscription.deleted&apos; || event.type === &apos;invoice.payment_failed&apos;) {

    const customerId = event.data.object.customer

    const { data: user } = await supabase.from(&apos;users&apos;).select(&apos;id&apos;).eq(&apos;stripe_customer_id&apos;, customerId).single()

    if (user) {

      await supabase.from(&apos;users&apos;).update({ plan: &apos;free&apos;, sub_status: &apos;inactive&apos; }).eq(&apos;id&apos;, user.id)

      await supabase.from(&apos;projects&apos;).update({ show_url: false }).eq(&apos;user_id&apos;, user.id)

    }

  }

  return NextResponse.json({ received: true })

}

9.1  Code Parser

// lib/codeParser.js

export function parseGeneratedCode(codeString) {

  const htmlMatch = codeString.match(/&lt;!--\s*index\.html\s*--&gt;[\s\S]*?(?=\/\*\s*style\.css|$)/)

  const cssMatch  = codeString.match(/\/\*\s*style\.css\s*\*\/[\s\S]*?(?=\/\/\s*script\.js|$)/)

  const jsMatch   = codeString.match(/\/\/\s*script\.js[\s\S]*/)

  if (!htmlMatch || !cssMatch || !jsMatch) {

    throw new Error(&quot;Generated code missing required file markers&quot;)

  }

  return {

    html: htmlMatch[0].replace(/&lt;!--\s*index\.html\s*--&gt;/, &apos;&apos;).trim(),

    css:  cssMatch[0].replace(/\/\*\s*style\.css\s*\*\//, &apos;&apos;).trim(),

    js:   jsMatch[0].replace(/\/\/\s*script\.js/, &apos;&apos;).trim(),

  }

}

// lib/githubBackup.js

const GITHUB_USER = process.env.GITHUB_USERNAME  // set this in .env to your GitHub username

const REPO        = &apos;onara-sites&apos;

// Fetch a fresh installation token from the FastAPI server

// (GitHub App tokens expire after 1 hour — always get a fresh one)

async function getGitHubToken() {

  const res = await fetch(`${process.env.PIPELINE_SERVER_URL}/github/token`, {

    headers: { &apos;x-pipeline-secret&apos;: process.env.PIPELINE_SECRET }

  })

  return (await res.json()).token

}

async function upsertFile(token, path, content, message) {

  const url = `https://api.github.com/repos/${GITHUB_USER}/${REPO}/contents/${path}`

  let sha = null

  const existing = await fetch(url, {

    headers: { Authorization: `token ${token}` }

  })

  if (existing.ok) sha = (await existing.json()).sha

  await fetch(url, {

    method: &apos;PUT&apos;,

    headers: { Authorization: `token ${token}`, &apos;Content-Type&apos;: &apos;application/json&apos; },

    body: JSON.stringify({

      message,

      content: Buffer.from(content).toString(&apos;base64&apos;),

      ...(sha ? { sha } : {}),

    }),

  })

}

export async function backupSiteToGitHub(projectId, { html, css, js }) {

  const token = await getGitHubToken()  // fresh GitHub App token

  const base = `sites/${projectId}`

  await Promise.all([

    upsertFile(token, `${base}/index.html`, html, `Add site ${projectId}`),

    upsertFile(token, `${base}/style.css`,  css,  `Add site ${projectId}`),

    upsertFile(token, `${base}/script.js`,  js,   `Add site ${projectId}`),

  ])

}

11.1  Redis Job Queue — Crash Recovery (HIGH PRIORITY)

The current in-memory asyncio queue loses all pending jobs if FastAPI crashes or restarts. A Redis queue persists jobs across restarts so no user loses a generation. This is a 30-minute swap — the pipeline logic does not change at all.

11.3  Blackboard Memory Pruning (HIGH PRIORITY)

The blackboard holds all agent outputs in FastAPI memory for the entire duration of a job. With 50 concurrent users generating sites, raw_code alone is 50+ KB per job. Prune each field once it has been consumed downstream.

# agents/pipeline.py — add pruning after each agent

async def run_pipeline(blackboard: dict):

    # ... agents 1-3 run ...

    # Agent 4: Planner — after it reads analyst/content/style, prune them

    await run_with_supervision(planner.run, &quot;Planner&quot;, key=&quot;blueprint&quot;)

    blackboard[&quot;analyst_output&quot;] = None   # consumed, free memory

    blackboard[&quot;content_output&quot;] = None

    blackboard[&quot;style_output&quot;] = None

    # Agent 6: Code Generator — prune the prompt after use

    await run_with_supervision(code_generator.run, &quot;Code Generator&quot;, key=&quot;raw_code&quot;)

    blackboard[&quot;prompt&quot;] = None

    # Agent 7: Debugger — prune raw_code after debugging

    await run_with_supervision(debugger.run, &quot;Debugger&quot;, key=&quot;debugged_code&quot;)

    blackboard[&quot;raw_code&quot;] = None

    # Agent 8: SEO — prune debugged_code after SEO pass

    await run_with_supervision(seo_agent.run, &quot;SEO Agent&quot;, key=&quot;seo_code&quot;)

    blackboard[&quot;debugged_code&quot;] = None

    # Agent 9: QA — prune seo_code after approval

    result = await qa_agent.run(blackboard)

    blackboard[&quot;qa_result&quot;] = result

    blackboard[&quot;qa_approved_code&quot;] = blackboard[&quot;seo_code&quot;]

    blackboard[&quot;seo_code&quot;] = None

    # Agent 10: Mobile Optimizer

    await mobile_optimizer.run(blackboard)

    blackboard[&quot;qa_approved_code&quot;] = None

11.4  Global Job Timeout (HIGH PRIORITY)

Without a hard timeout, a single stuck job can block the queue for hours. 5 minutes is enough for any legitimate generation — if it takes longer something is wrong. Add this to the RQ enqueue call in 11.1 (job_timeout=300) and also add a FastAPI-level guard:

# agents/pipeline.py — wrap entire pipeline in a timeout

import asyncio

async def run_pipeline(blackboard: dict):

    try:

        await asyncio.wait_for(

            _run_all_agents(blackboard),

            timeout=300.0  # 5 minute hard limit

        )

    except asyncio.TimeoutError:

        blackboard[&quot;phase&quot;] = &quot;error&quot;

        blackboard[&quot;errors&quot;].append(&quot;Pipeline exceeded 5 minute timeout&quot;)

        raise

11.5  Smarter ollama_cloud Exception Handling (MEDIUM PRIORITY)

Currently ollama_cloud catches all exceptions identically. A 429 rate limit (temporary) and a 500 server error (persistent) should be handled differently. Waiting 15 seconds on a 500 just wastes time.

# lib/ollama_client.py — differentiate exception types

import httpx

def ollama_cloud(model: str, prompt: str,

                 fallback: str = &quot;llama3.3:8b&quot;) -&gt; str:

    try:

        r = cloud_client.chat(

            model=model,

            messages=[{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: prompt}]

        )

        return r.message.content

    except httpx.HTTPStatusError as e:

        if e.response.status_code == 429:

            # Rate limited — wait then retry once before falling back

            import time; time.sleep(15)

            try:

                r = cloud_client.chat(model=model,

                    messages=[{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: prompt}])

                return r.message.content

            except Exception:

                pass  # fall through to local

        # 5xx or other — fall back immediately, no wait

        print(f&quot;Cloud error {e.response.status_code}, falling back to {fallback}&quot;)

        return ollama_local(fallback, prompt)

    except Exception as e:

        # Timeout, connection error — fall back immediately

        print(f&quot;Cloud connection error, falling back to {fallback}: {e}&quot;)

        return ollama_local(fallback, prompt)

11.8  GitHub App Token Caching (MEDIUM PRIORITY)

The GitHub App installation token is currently generated on every deployment request. Each generation costs an httpx round trip to GitHub. Cache it in FastAPI memory with a 50-minute TTL — GitHub tokens last 60 minutes, so 50 minutes gives a safe buffer.

# lib/github_auth.py — add token cache

import jwt, time, httpx, os

from typing import Optional

_token_cache: Optional[str] = None

_token_expires: float = 0

def generate_installation_token() -&gt; str:

    global _token_cache, _token_expires

    # Return cached token if still valid (50-min TTL)

    if _token_cache and time.time() &lt; _token_expires:

        return _token_cache

    payload = {

        &quot;iat&quot;: int(time.time()) - 60,

        &quot;exp&quot;: int(time.time()) + 540,

        &quot;iss&quot;: os.getenv(&quot;GITHUB_APP_ID&quot;),

    }

    jwt_token = jwt.encode(payload, os.getenv(&quot;GITHUB_APP_PRIVATE_KEY&quot;),

                           algorithm=&quot;RS256&quot;)

    r = httpx.post(

        f&quot;https://api.github.com/app/installations/{os.getenv(&quot;GITHUB_APP_INSTALLATION_ID&quot;)}/access_tokens&quot;,

        headers={&quot;Authorization&quot;: f&quot;Bearer {jwt_token}&quot;,

                 &quot;Accept&quot;: &quot;application/vnd.github+json&quot;}

    )

    r.raise_for_status()

    _token_cache = r.json()[&quot;token&quot;]

    _token_expires = time.time() + 3000  # 50 minutes

    return _token_cache
